How to read
  Pass gate is "lower fault cost when larger anon pages amortize zeroing."
  Within each run, hugeprefer (PMD) finishes the same 1024 MiB write-touch in
  ~15.6–16.4% of nohuge wall-ns (≈6.1–6.4× faster) on all 3 runs, with
  exact 512:1 reduction in minor faults (262144 → 512) and +512 PMD
  thp_fault_alloc / zero fallback. Checksums match → same stores.
  Run-to-run noise on the ratio is ~(0.1635−0.1557)/0.1587 ≈ 4.9% relative;
  the ~84% fault_ns cut clears that noise with the same sign on all 3 pairs.
  Aggregate perf cycles wrap both paths and are not the pass metric.
  tlb_misses unavailable on this CPU — PMD TLB benefit inferred from minflt
  and PMD install stats, not from missing PMU events.

Anonymous PUD (still missing)
  create_huge_pud() still returns FALLBACK for anon. A true 1 GiB anonymous
  page would be new kernel work; not attempted. Closing roadmap line still
  applies: "PMD and mTHP so zeroing is amortized."

Verdict: PASS (policy / application-path) — no kernel patch
  - MADV_HUGEPAGE under stock THP=madvise installs PMD anon pages and
    amortizes write-fault zeroing vs MADV_NOHUGEPAGE on every run.
  - Mid-size mTHP (64k..1M) exists in sysfs but defaults [never]; enabling
    is `echo always > .../hugepages-NkB/enabled` (optional; not required
    for the PMD win shown here). Workload supports ANONFAULT_ENABLE_MTHP=1.
  - Anonymous PUD remains unimplemented — document only; do not invent a
    1 GiB anon patch for this task.
  - Recommendation: callers that allocate large anon should MADV_HUGEPAGE
    (or run with transparent_hugepage=always). Kernel left on known-good
    7.2.9-t9 after measure; THP sysfs left at stock defaults.
