Roadmap ask
  "Account for cache misses, not only CPU time." Record LLC misses and NUMA
  locality next to CPU time on locality tasks. Accounting task, not a new
  scheduler.

Survey — what already existed
  - collect.sh already probed cycles, instructions, cache-references,
    cache-misses, LLC-load-misses, dTLB/iTLB-load-misses, context-switches,
    cpu-migrations; wrote cache_misses / cache_misses_per_kinstr into
    metrics.env; schedstat ttwu_local/remote with --schedstats; vmstat
    numa_hint_faults_delta.
  - Prior runs on this box left llc_load_misses=n/a and tlb_misses=n/a with
    perf_dropped=LLC-load-misses,dTLB-load-misses,iTLB-load-misses.
  - Root cause (Task 10 finding): probe_perf matched perf list with a
    case-sensitive grep. On this CPU perf list prints lowercase
    llc-load-misses / dtlb-load-misses / itlb-load-misses, so the uppercase
    candidates were dropped BEFORE perf stat was tried — even though
    perf stat -e LLC-load-misses (and the TLB events) accept and count.
  - Additional live events on this PMU (confirmed with perf stat):
    mem_load_retired.l3_miss, mem_load_retired.l3_hit, longest_lat_cache.miss.
  - Topology: numa_nodes=1, llc_domains=1, llc_size=12288K, shared 0-11.
    numa_balancing=0. PSI present. /proc/schedstat present.

Harness changes (Task 10) — no kernel patch
  1. collect.sh probe_perf: case-insensitive perf-list match; keep canonical
     event names for delta.awk; also probe mem_load_retired.l3_{miss,hit}
     and longest_lat_cache.miss as LLC fallbacks.
  2. lib/delta.awk: accept lowercase aliases; map to canonical; emit
     cache_miss_rate, llc_misses_per_kinstr, l3_misses, l3_hits,
     ttwu_remote_frac; fall back LLC from longest_lat / l3_miss when needed.
  3. collect_meta: always write meta/topology.txt (numa_nodes, llc_domains,
     llc_size, numa_balancing, single-node/single-LLC notes).
  4. snapshot: PSI memory/cpu/io before+after under run/psi/.
  5. tasks.conf Task 10 primary metrics expanded to include llc_load_misses,
     cache_miss_rate, llc_misses_per_kinstr, l3_misses, tlb_misses,
     ttwu_remote_frac / ttwu_remote_delta beside cycles.
  6. workloads/locality_account.sh: prepare helper writes locality_caps.txt
     (which PMU events accept); run path reuses migrate_storm.
  7. compare.sh labels for the new metric keys.

What was NOT done (and why)
  - No 7.2.9-t10 kernel, no 0010-*.patch, baseline tree untouched.
  - No fake LLC-miss numbers and no invented PMU events.
  - Scheduler locality policy changes would not show migration wins on
    1 LLC / 1 NUMA (see Task 2). Task 10 is accounting, not placement.
  - A gated kernel counter was not justified: the missing data was a
    harness probe bug, not a missing kernel ABI. /proc/schedstat,
    /proc/vmstat numa_*, PSI, and the HW PMU already expose what we need.

Hardware limits (critical — usable now vs needs multi-LLC)
  USABLE NOW on this box:
    - cache_misses + cache_miss_rate + cache_misses_per_kinstr next to cycles
    - LLC-load-misses + llc_misses_per_kinstr + PEBS l3_misses/l3_hits
    - dTLB/iTLB / tlb_misses
    - ttwu_remote_frac (runqueue wake locality) with --schedstats
    - topology.txt + PSI snapshots on every run
  NOT PROVABLE here (needs multi-LLC / multi-NUMA hardware):
    - Cross-LLC preferred-placement wins (Task 1/2/13 style)
    - Remote NUMA access rates / numa_hint_faults movement (always 0 here;
      numa_balancing=0 and only one node)
    - Unbound workqueue LLC-pin vs node-RR (Task 13) — survey-only note below

How to read
  Noise on cache_misses / llc_load_misses across S1..S3 is large on
  migrate_load (LLC misses swing ~5×). That is expected for a migration
  storm on one shared L3 — do not treat a single pair as a locality win.
  The Task 10 success criterion is that the counters are collected and
  sit next to cycles in metrics.env / compare.sh --task 10, with n/a only
  when the PMU truly rejects the event (perf_dropped).

Verdict: PASS (harness / telemetry) — not a kernel win claim.
  - Cache-miss, LLC-miss, TLB-miss, l3 hit/miss, and ttwu_remote_frac are

  - Single-LLC / single-NUMA hardware: usable for miss-rate accounting;
    NOT usable to prove cross-LLC or remote-NUMA policy wins.
