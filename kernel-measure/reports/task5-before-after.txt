Survey (Phase 1)
  Baseline tree: /home/kernelmaster/kernel-build/linux-7.2.9-baseline (not modified).
  filemap_read(): hot buffered path copies via copy_folio_to_iter() for every
  userspace pread of an already-cached folio.
  IOCB_DONTCACHE / dropbehind: marks folios to drop AFTER the copy (cold/
  streaming pollution control). Does not skip the copy on a hot hit.
  O_DIRECT (generic_file_read_iter + IOCB_DIRECT): mapping->a_ops->direct_IO,
  DMA into user buffer — no page-cache copy. App must align buf/off/len.
  mmap (filemap_map_pages): maps uptodate folios into the VMA; after fault-in,
  loads are userspace DRAM access with no syscall and no copy_folio_to_iter.
  Roadmap: "Better mechanism: mmap or O_DIRECT — application-path change,
  not a new kernel read syscall." Full notes: reports/task5-survey.txt.

How to read
  Pass gate is "lower cycles for same read work when mmap/O_DIRECT avoids
  buffered copy." Per-path wall_ns for equal bytes is the direct proof:
  mmap finishes the same 6000 MiB in ~64% of buffered wall (ratio 0.638–
  0.663 on all 3 runs) — the copy_folio_to_iter / pread tax is gone after
  fault-in. O_DIRECT on an already-hot page-cache file is ~2.8–3.1× slower
  on wall here because it re-reads from NVMe instead of DRAM; that is the
  expected hot-cache comparison, not a failure of O_DIRECT. O_DIRECT still
  avoids the page-cache copy (and double-buffering) when the application
  owns its own buffer pool — a different cost model than "hot pread vs DIO".
  Whole-run perf cycles stay flat by construction (all three paths always
  run); do not treat aggregate cycles as the pass metric.

Verdict: PASS (application-path) — no kernel patch
  - mmap beats hot buffered pread on every run for the same bytes
    (~36% less wall-ns; ~1.5–1.6× throughput).
  - O_DIRECT correctly bypasses page-cache copy but loses to hot buffered
    on wall when data is already cached; report that honestly.
  - No 0005 patch / linux-7.2.9-t5: inventing a second buffered-read path
    that skips the copy would just be mmap/O_DIRECT under another name.
  - Recommendation: callers that need hot zero-copy should mmap (or use
    O_DIRECT when they manage their own cache). Kernel left on known-good
    7.2.9-t9 after measure.
