Survey (Phase 1)
  Roadmap: "Stop reclaim from splitting large anonymous folios."
  Cited mechanism: shrink_folio_list splits when matching swap slot missing;
  better path = swap_table clusters kept at folio order.

  7.2.9 already implements that better path:
    CONFIG_THP_SWAP=y
    mm/swap_table.h per-cluster table (SWAPFILE_CLUSTER = HPAGE_PMD_NR)
    folio_alloc_swap() at folio_order; order-aware free/nonfull/frag lists
    shrink_folio_list: try whole-folio swap first; only then
      split_folio_to_list + THP_SWPOUT_FALLBACK on failure
    Partially mapped: split immediately (free unmapped pages without IO)
    try_to_unmap(..., TTU_SYNC | TTU_SPLIT_HUGE_PMD) for large folios

  Existing knobs (not a new sysctl):
    transparent_hugepage/shrink_underused (stock 1)
    khugepaged/max_ptes_none (stock 511 = disables thp_underused())
    THP enabled/defrag, MADV_*, swap size/fragmentation

  Full prep: reports/task8-survey-prep.txt.

How to read
  Pass gate: prove split path on stock; show existing reclaim already keeps
  large anon folios whole when folio_alloc_swap(order) succeeds; no OOM;
  do not ship ungated never-split.
  Partial: exact 512 splits / 512 deferred / 512 split_pmd on every run —
  path fires, far past noise, same sign on all 3.
  Underused: 510/512 whole THP swpouts, only 2 fallbacks/splits on every
  run — same sign on all 3 pairs vs partial (split↓, swpout↑). That is the
  in-tree "keep folio at order" behavior the roadmap asked for.
  shrink_underused A/B with stock max_ptes_none=511 is a no-op
  (thp_underused short-circuits); with max_ptes_none=64, reclaim still
  preferred whole swpout over deferred underused split in smoke — further
  evidence the swap path already expresses the intent.

Verdict
  PASS (policy / existing in-tree) — rely on CONFIG_THP_SWAP + order-aware
  swap_table clusters; reclaim already avoids splitting when a matching
  swap cluster exists. Splits for partially mapped folios and for
  THP_SWPOUT_FALLBACK must remain (reclaim progress). Do NOT ship an
  ungated never-split patch. No 7.2.9-t8 / 0008-*.patch.

Recommendation
  - Operators: ensure swap is large enough and not order-0 fragmented if
    THP/mTHP swpout success matters (watch thp_swpout vs thp_swpout_fallback).
  - shrink_underused=0 only if max_ptes_none is lowered and deferred
    underused splits are unwanted; stock max_ptes_none=511 already disables
    underused detection.
  - Leave reclaim free to split on partial map / swap-alloc failure.
  - Application path: MADV_HUGEPAGE for large anon (Task 6); avoid
    punching holes inside THPs if keeping PMD folios matters.
